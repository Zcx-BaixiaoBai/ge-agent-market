# 办公业态报告总控

> **市场版说明**：本包包含「报告总控」技能、知识库、BI 取数/认证/PDF 脚本和示例报告；六个子技能不在包内。
> 若当前环境未安装子技能，直接按本文件与 `references/knowledge_base/` 的规则逐章完成。

统筹写字楼经营分析报告的全流程：读取 Excel → 调用六个子 Skill → 汇总十一个章节 → 自检 → 输出管理层报告。

## 首次配置（环境变量）

本包所有 OA/BI 账号、工号、内网地址都从环境变量读取，不内置任何凭证。首次使用先装依赖：

```bash
python3 -m venv .venv && . .venv/bin/activate   # Windows: .venv\Scripts\activate
pip install -r scripts/requirements.txt
cd scripts && npm install && cd ..
```

再设置环境变量（按实际环境替换尖括号内容）：

```bash
export BI_BASE="https://<观远BI地址>"
export BI_ORIGIN="$BI_BASE"
export OA_URL="http://<OA地址>/wui/index.html"
export OA_SSO_URL="http://<OA地址>/interface/ywf/GoToOtherSys.jsp?syscode=001"
export OA_LOGIN_ID="<OA工号/账号>"
export OA_PASSWORD="<OA密码>"
export GUANCLI_BIN="guancli"                                  # 可选
export GUANCLI_CONFIG="$HOME/.config/guancli/config.json"     # 可选，按平台
export PROJECT_ROOT="$(pwd)"                                  # 可选，数据/输出根目录
```

Windows PowerShell 用 `$env:BI_BASE = "..."` 形式；正式部署建议把同样变量放进平台密钥管理。
`scripts/fetch_bi_data.py` 会读取这些变量并通过 `scripts/bi_auth_refresh.js` 自动刷新 BI token。

## 数据文件来源（BI 自动化取数）

- **默认数据文件**：`data/写字楼经营分析-BI取数_{报告截止日}.xlsx`（由 `scripts/fetch_bi_data.py` 从 BI 自动取数产出）。报告截止日缺省=昨日；用户指定日期时用对应文件。
- **兼容旧模板**：若上述文件不存在，回退到 `data/写字楼出租率-数据模板.xlsx`（人工维护，结构为旧版，行号见各子 Skill 括注）。
- **sheet 识别一律用前缀匹配**，不要写死完整 sheet 名（期间会变，如 `B权责1-10月累计分析`、`B权责1-11月累计分析`）。前缀 → 用途对照见下节。
- **取数日志 sheet**（名 `取数日志`）记录报告截止日、期间开始、各卡行数与警告；若其中有「⚠️ 警告」，报告第十一章必须如实引用，对应章节标注「数据未提供/待补全」，严禁编造。

## 示例与模板

- `frontend/办公业态经营分析_2026年10月_金鹰版.html`：现行报告样例，作为视觉/结构基准（含真实经营数据，仅内部使用）。
- `frontend/金鹰版-内网部署模板.html` + `frontend/vendor/`：内网无外网时可整目录托管。
- `scripts/gen_pdf_jinying.js <input.html> <output.pdf>`：按 A4 / 5mm 边距 / 封面独占页导出 PDF；`CHROME_BIN` 可指定浏览器。

## 十一个章节骨架

1. 管理层摘要（结论先行，7 要素）
2. 关键指标总览（汇总表）
3. 出租率与空置（项目明细表）
4. 合同动态与净吸纳（项目明细表 + 净流失排名）
5. 租金与量价（存量/新增对比 + 各项目租金单价变化表）
6. 竞品与项目定位（竞品对比表）
7. 租户储备与招商漏斗（漏斗表 + 重点客户表）
8. 财务权责与全年预测（财务表 + 缺口计算）
9. 风险预警（分条量化）
10. 行动建议（30天/90天/考核建议）
11. 数据口径与异常说明（口径说明 + 异常汇总表）

## 结论前置要求

- 每章第一句必须是结论性判断，后跟数据表格
- 管理层摘要必须包含：总体判断、全年利润最大拖累、出租率与空置、合同动态、租金量价、储备与招商、需管理层决策事项
- 风险预警每条必须量化（面积/金额/百分比）
- 行动建议分为 30天内、90天内、考核建议

## 口径优先级

数据来源按以下优先级取值（高优先级覆盖低优先级）。**括号内为 BI 取数产出文件的实际 sheet 名（前缀匹配）**：

1. `B权责`（如 B权责1-10月累计分析）— 面积、出租率、收入、支出、利润、EBITDA、同比、全年预估、租金变化（最高）
2. `A基础信息`（出租+收入）— 出租率/收入累计目标与达成率
3. `B收入支出明细` / `B出租面积明细` — 项目级收入支出、可租赁/已出租/净增长面积（B权责的明细展开，可交叉校验）
4. `C合同情况`（本年累计）— 新签/续签/掉铺数量·面积·明细
5. `C流失统计`（本年累计）— 掉铺客户流失原因、代表租户、经营类别
6. `F储备转化分析` + `F储备明细` — 招商漏斗（可跟进/已转化/已流失）
7. `D办公业态竞品` — 竞品租金、出租率、优劣势、对抗策略

> ⚠️ 旧模板中的 `权责（1-6月）`、`B整场平均租金单价`、`C1-8月合同情况`、`F租户储备分析` 在 BI 产出文件中**已不存在**；对应指标改用上表 sheet。租金单价取 `B权责` 表「租金变化情况」行组（R28-R29），竞品租金单价取 `D办公业态竞品` 表 G 列。

详细口径规则见 `references/knowledge_base/口径规则.md`，各 sheet 行号布局与 BI 结构差异见 `references/knowledge_base/数据源映射.md`「一·D」。

## 子 Skill 调用顺序

按以下顺序依次调用六个子 Skill，每个子 Skill 输出对应章节内容；若当前环境没有这些子技能，直接按 `references/knowledge_base/` 的规则完成对应章节：

1. **出租率与空置分析** → 输出第三章（出租率与空置表 + 空置排名）
2. **合同动态与净吸纳** → 输出第四章（合同动态表 + 净流失排名）
3. **租金与量价分析** → 输出第五章（量价判断 + 存量/新增租金对比）
4. **财务权责与全年预测** → 输出第八章（财务表 + 缺口计算）
5. **竞品对标** → 输出第六章（竞品对比表 + 竞争定位判断）
6. **租户储备与招商漏斗** → 输出第七章（漏斗表 + 重点客户表）

调用后汇总为完整报告，补充第一章（管理层摘要）、第二章（关键指标总览）、第九章（风险预警）、第十章（行动建议）、第十一章（数据口径与异常说明）。

## 自检清单

报告生成后，逐项检查：

- [ ] 是否结论前置（每章第一句为结论）
- [ ] 是否包含全部十一个章节
- [ ] 是否标注所有缺失数据（"数据未提供/待补全"）
- [ ] 是否标注所有异常（按异常规则.md 的 9 类异常）
- [ ] 是否编造数据（严禁，所有数值必须来自 Excel 或公式计算）
- [ ] 是否统一单位（金额万元、面积㎡、租金元/㎡/天、百分比保留1位小数）
- [ ] 是否给出可执行建议（行动建议分 30天/90天/考核）
- [ ] 是否区分已转化/可跟进/已流失（储备漏斗三类状态）
- [ ] 是否指出全年利润最大拖累项目（管理层摘要必含）

## 工作流程

### 1. 确定数据文件与报告期间
- 定位数据文件：优先取 `data/` 下最新的 `写字楼经营分析-BI取数_YYYY-MM-DD.xlsx`（文件名日期=报告截止日）；无则回退旧模板 `写字楼出租率-数据模板.xlsx`。
- 识别报告期间：读 `B权责` 前缀 sheet 名（如「B权责1-10月累计分析」→ 2026年1-10月）；读 `取数日志` sheet 确认报告截止日、期间开始（2026-01-01）与警告项。
- C 表期间为「年初至今累计」（本期开始=2026-01-01），报告文案须表述为「本年累计」而非「本周」。

### 2. 加载知识库
读取 `references/knowledge_base/` 下的指标字典、口径规则、异常规则、报告模板、报告样式-财务风、数据源映射（BI sheet 结构），获取指标定义、口径规则、异常规则、报告模板。

### 3. 调用子 Skill
按顺序调用 6 个子 Skill，每个子 Skill 从数据文件按前缀匹配定位 sheet、按「数据源映射.md 一·D」的行号布局读取数据，执行计算，输出对应章节 Markdown。

### 4. 汇总与补充章节
汇总 6 个子 Skill 输出，补充第一章（管理层摘要）、第二章（关键指标总览）、第九章（风险预警）、第十章（行动建议）、第十一章（数据口径与异常说明）。

### 5. 自检
按自检清单逐项检查，修正不合格项。

### 6. 输出
将最终报告保存为 Markdown 文件到 `output/` 目录，文件名格式：`办公业态经营分析_YYYY年MM月.md`，并把文件路径交付给用户。

如需输出 HTML 版本，必须按 `references/knowledge_base/报告样式-财务风.md` 的设计令牌与元素规范生成（金鹰暖色财务风：米色纸张质感背景、金色主色、深棕表头、宋体封面标题、顶部毛玻璃导航 + 左侧默认展开浮动目录、简要分析/结论/问题/建议四类分析卡片、Chart.js 图表必须带数据标签），不得使用其他风格。PDF 用 `scripts/gen_pdf_jinying.js <input.html> <output.pdf>` 生成：A4 纵向、四边 5mm 页边距、封面独占一页、章节间不强制分页；浏览器路径可用 `CHROME_BIN` 指定。

## 维护知识库

当新增指标、调整口径或添加报告模板时，直接编辑 `references/knowledge_base/` 下对应文件。保持每个条目格式统一，便于后续检索和复用。

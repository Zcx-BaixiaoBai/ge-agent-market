# 任务助手（ge-workbench-task-assistant）

把四个任务系统放进一页：**金鹰PLAN**（筹建专项计划）、**巡检维保**（IPMS）、**金鹰安全**、
**工单任务**（金鹰智慧物业运营平台）。

打开工作台先看四张系统卡：每个系统有多少未完成、72 小时内到期、已过期、今天完成。
卡片下方是跨系统合并的「需要优先处理」清单和自动生成的「处理建议」。
点进任意系统是子页，可以按状态、分类、到期日期筛选，也能直接搜索任务名、负责人或分类。

## 界面形态

整页业务看板，不常驻会话区。

- 首次进入：即使没有会话也直接显示总览；没有连接任何系统时给出「去连接系统」和「先看演示数据」两个入口。
- 需要 AI 协助时点工具栏的「让 AI 分析」：宿主为该工作台创建/恢复会话，右侧显示对话区，
  并把当前汇总写成草稿，由用户确认后发送。
- 演示数据只用于查看界面，页面上会持续显示「演示数据」提示，不会与真实数据混在一起。

- 只看最近半年：任务的到期、创建、完成时间都在半年前的不再计入首页和子页。
- 首页可按项目筛选：工具栏「项目」里勾选要看的项目，汇总、图表、子页都会跟着切换；不选就是全部。
- 每个系统的账号只在「连接设置」里填一次，保存在本机 `dshHomePath('task-assistant')` 目录，权限 0600；
  密码只存在本机这个目录里，界面不回显；重连时密码留空即可沿用，不需要重新输入。
- 连接设置里只需要两样东西：四个系统的账号密码，以及一个多模态模型的接口地址、API Key、模型名。
  后者用于识别工单系统登录时的算式验证码（任意 OpenAI 兼容的视觉接口均可）。

- 「即将到期」默认指 72 小时内到期；「已过期」指未完成且到期时间已过。
- 工单系统如果没有明确的到期字段，用「创建时间 + 72 小时」估算，这类估算会在「处理建议」里说明，不会当作真实时限。

## 指标口径

- **未完成**：任务状态不是「已完成 / 已归档 / 已作废」。
- **已过期**：未完成且到期时间早于当前时间。
- **72 小时内到期**：未完成且到期时间在未来 72 小时内。
- **今日完成**：状态为已完成且完成时间落在今天（Asia/Shanghai）。
- 金鹰PLAN 的「逾期标识 / 预警标识」由系统给出；巡检维保与金鹰安全的状态文本里带「逾期」时也计入已过期。
- 金鹰安全的历史已整改隐患（状态 2，上万条）不拉取，只取待整改/处理中的 844 条与 66 条履职计划。

## 本地数据

```
dshHomePath('task-assistant')/
├── settings.json   # 各系统账号名、连接状态、是否使用演示数据
├── secrets.json    # 账号密码、多模态模型配置、登录 token（0600），不会被任何接口回显
├── snapshot.json   # 最近一次拉取的任务快照
└── debug/          # 连接失败原因与各系统首个字段样本，仅本机可读
```

卸载工作台不会删除该目录。

## 开发

```bash
npm run build   # esbuild 打包客户端单文件到 lib/client.js
npm test        # 服务端接口 + 客户端注册测试
npm run check   # 构建 + 测试
pnpm pack       # 产出可安装的 .tgz
```

`register()` 中的 `repository` 是本地开发预留的身份地址，未发布到任何仓库。

## 尚未验证

- 金鹰PLAN、巡检维保、金鹰安全、工单任务的真实登录与取数，需要使用者自己的账号与内网权限，尚未在本机实测；
  连接页已提供每个系统的实际接口与错误反馈。
- 金鹰安全的账号登录（SM2 加密）、巡检维保的账号登录与工单系统的验证码自动识别都没有用真实账号跑过；
  连接失败时会把原因写到 `debug/connect-<系统>.json`，取数成功后会把真实字段名写到 `debug/<系统>.json`；
  接口和字段按系统前端与已验证的取数脚本整理，失败时会在连接页给出原系统返回的提示。
- 第一次连接金鹰安全或工单系统时如果报错，把错误信息发回对话即可按真实返回调整映射。
